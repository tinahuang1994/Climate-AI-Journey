两种模式的本质差异
你的角色从"持续指令"变成"目标定义 + 结果评审"
氛围编程 / Vibe Coding
感觉驱动
每 5 分钟来问你一次
靠持续输入维持方向
靠"感觉对了"判断完成
失败模式：目标漂移，无限循环
适合：一次性原型、探索
Agentic Engineering
目标驱动
启动时定义，完成时评审
靠预定义约束维持边界
靠验收清单判断完成
失败模式：目标定义不清
适合：生产功能、完整模块
核心原则
三个原则决定了 AI 能不能真正替你工作
01
先定义目标，再开始执行
在写第一行代码之前，写清楚 Goal（终态）、Constraints（边界）、Done When（验收标准）。AI 有了完整地图，才能自主导航。
Goal-First
02
让 AI 自主运行，不要盯着它
启动后，真正地离开。你是门控点，不是监控员。中途打断等于把 Agentic Engineering 退化回氛围编程。
Autonomous Run
03
用验收标准评审，不靠感觉
拿到结果时，对着 Done When 清单逐条核查。有测试就跑测试。评审的是"是否满足预定义条件"，不是"是否顺眼"。
Criteria-Based Review

操作流程
每一个 Agentic 任务都走这五步
1
任务分解 把大目标拆成 2–4 个独立任务块。每块有自己的开始状态和验收标准，20–40 分钟可完成。
2
写 /go 启动指令 填入 Goal + Constraints + Done When。避免"让它更好""优化一下"这类模糊措辞。
3
设置门控规则 告诉 Claude 什么情况才来问你（只有三种：歧义 / 破坏性操作 / 硬性技术阻断）。其余自行决策。
4
启动，然后离开 字面意义上的离开。你是门控点，不是监控员。坐着盯着它跑，等于自己破坏了这套系统。
5
对照 Done When 评审 逐条核查验收标准，跑测试，看 git diff 范围是否合理。有问题就修正 Goal 定义，重新启动。
真实案例
Climate Dossier 证明 PRD + Eval + 门控可以让 AI 工程化运行
项目
双语 RAG 气候知识库，覆盖 IPCC AR6、SBTi 标准、G20 NDC 三个模块，含完整引用和战略解读层。
评估层
25 个 golden test cases，25/25 passing。每个新模块必须先写测试，测试通过才算完成。
核心原则
PRD → CLAUDE.md → eval 用例 → 构建 → 评审。每一层都在收窄 AI 的决策空间，不是扩大它。
Agentic 工作流
1
PRD.md 定义目标 — 4 个 Must-Have，技术限制，用户画像。代码还没开始写。
2
CLAUDE.md 固化约束 — 不用 Vercel，不用 Google Fonts，LLM 选型，门控规则。Claude 每次启动都继承这些决定。
3
先写 eval，再构建 — 测试用例就是 Done When。NDC 模块：8 条 eval 用例写好后才开始 ingestion。
4
Staging → Prod 门控 — dev DB 跑通 eval 才能 promote 到 prod。破坏性操作有结构化门控。
5
一行命令评审 — python eval/run_eval.py 跑完，25/25 pass = 完成。
工具选择
Claude Code 和 OpenAI Codex 各有适合的场景
Claude Code
Anthropic · CLI 工具
运行环境 本地 CLI（你的机器）
配置系统 CLAUDE.md（持久化上下文）
自定义命令 可定义 skills（/go 等）
代码访问 读整个本地 codebase
最适合 本地开发 + 复杂项目规范
Codex
OpenAI · Cloud Agent
运行环境 云端沙箱（OpenAI 服务器）
配置系统 无等价持久化配置
并行能力 支持多个任务同时运行
代码访问 连接 GitHub repo（云端）
最适合 GitHub-first + 并行任务场景
💡 工具会变，工程思维不会。Goal + Constraints + Done When 的框架适用于任何 agentic 工具。
升级路径
Agentic Engineering 分四个阶段，你今天就可以从第一阶段开始
阶段 1
单任务 Agentic 运行
掌握 /go 模板。把一个任务写成 Goal + Constraints + Done When，让 Claude 跑完不打断。
阶段 2
项目级规范沉淀
建立项目 CLAUDE.md。把每一个重要决定实时写进去，让上下文在每次会话中自动继承。
阶段 3
可重复模块化流程
写 onboarding 协议和 eval harness。流程本身成为工程产出，任何新模块都可以按协议复制执行。
阶段 4
自动化闭环
接入 CI/CD。Eval 通过才允许 merge。你从工程执行者变成系统设计者。
